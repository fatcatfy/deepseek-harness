# 06 消息系统 —— 会话日志即模型记忆

> 官方参考：[../packages/core/session/README.md](../packages/core/session/README.md)、持久化事件目录 [../docs/persistence-catalog.md](../docs/persistence-catalog.md)、格式状态 [../docs/session-format-status.md](../docs/session-format-status.md)

## 1. 核心理念：Model-visible ⟺ Logged

[../docs/architecture.md](../docs/architecture.md) 的权威表述：**"Model-visible means logged. Every model request must be reconstructable from the log."**

这不是口号，而是由构造保证的不变量：

- 模型历史**只能**由 `Session.deriveMessages()` 从 surface 派生；任何模型可见输入必须先成为 session 事件（system prompt 是 `system/message` 事件、注入上下文是带 source 的 `user/message` 事件）。
- `agent/request` waterfall 被文档明言不能改消息——插件改消息内容的唯一合法通道是注册**纯投影**（`SessionMessageProjection`）。
- 会话日志是 fork、resume、transcript、遥测、持久化共同的祖先；live UI 的增量性才来自 `agent/assistant-stream` 事件。

## 2. SessionEventMap：merge-extensible 的事件词汇

声明于 [packages/core/session/src/types.ts](../packages/core/session/src/types.ts)，是"merge-extensible、append-only 的 agent 交互事实源"。插件通过 `declare module '@deepseek-ai/dsh-session/types'` 合并新事件（例：compaction 组合并 `compaction/*` 四事件）。

代表性事件：

| 事件 | 载荷要点 |
|---|---|
| `turn/start` / `turn/end` | 回合边界；`turn/end` 携带 `TurnEndReason` |
| `step/start` / `step/end` | 一次模型调用 + 其工具执行 |
| `user/message` | 人类输入 / `agent.inject()` 合成上下文 / goal 续轮；`source` 字段区分 |
| `developer/message` | 增量 agent 会话变更（如工具新增） |
| `system/message` | 渲染后的 system prompt 是 **surface 节点 0**，不是请求头字段 |
| `assistant/message` | 组装完成的助手消息；**内嵌精确压缩的定时模型流**（模型输出与计费一起持久化）；取消的流以 `interrupted: true` 定稿已送达前缀 |
| `assistant/attempt` | 未产生 surface 消息的失败/重试/取消尝试——保留原始流但不伪造模型可见历史 |
| `tool/call` / `tool/result` | 以 `callId` 配对；`tool/call` 的 `arguments` 是模型原始 JSON 字符串；`tool/result` 可带 `meta`（工具私有展示载荷）与 `error` |
| `request/header` / `request/context` | 请求完整头快照（call config + tools）与路由元数据 |
| `session/end-seed` | fork 继承切割标记 |

`SessionEvent<T>` 是对 `type` 的判别联合——`switch (event.type)` 直接窄化 `event.data`，无需断言。

## 3. Surface 机制：模型可见面

只有五类事件产生 LLM 消息、可进入有序 surface（[surface.ts](../packages/core/session/src/surface.ts)）：

```ts
SurfaceEventType = 'system/message' | 'developer/message' | 'user/message'
                | 'assistant/message' | 'tool/result'
```

- **SurfaceOp**：每个 surface 事件必须声明如何加入 surface——`'append'` 或 `{ op: 'replace', startSeq, endSeq }`（压缩的替换用 replace）。
- **sourceEventSeqs**：system/user/tool 事件引用其派生自的更早事件（assistant 例外——它内嵌流）。
- `SurfaceManager` 是 surface 接受与投影状态的唯一增量 owner；`foldSurface`、`deriveEventMessage`、`isAppendSurfaceEvent`（人类 transcript 的判据：replace 拷贝是模型可见专用的，不应抹掉用户已见的对话）、`isReplacementSurfaceEvent` 都从此导出。
- `SessionMessageProjection`：插件注册的纯函数解释器，用于"改变现有消息内容而不改节点成员/消息身份"（如 image-offload）。

## 4. 写入路径：Session.append

[index.ts](../packages/core/session/src/index.ts) 的 `Session.append(type, data, opts)`：

1. `snapshotJsonValue(data)` **一次遍历**完成"读取-校验-复制"（防带状态 getter 在校验与存储间返回不同值）；非无损 JSON（BigInt/循环等）在写入点抛错。
2. `validateSessionEventData` + `SurfaceManager.validateNext`——候选先计划后入 log，失败不部分污染 surface。
3. `seq = log.length`（连续性契约）→ `deepFreeze` → 推入内存 log。
4. 热路径**不阻塞 I/O**：持久化插件异步缓冲；提交后经 publication hooks 发布 `session/event`（fire-and-forget，观察者失败按 listener 遏制）。

Cordis 层事件（声明合并到 Context）：`session/created`、`session/disposed`、`session/event`（追加流）、`session/flush`（**awaited parallel 持久性屏障**，唯一入口 `SessionStore.flush()`）。

**落盘时机**由 [session-checkpoint-policy](../packages/session/session-checkpoint-policy/src/index.ts) 策略化：`llm/stream` 前 flush（保证请求前缀落盘后才派发 adapter）、顶层 `tools/execute` 前 flush、`agent/pre-step` flush 上一批。

## 5. 重建与派生

- **派生模型历史**：`Session.deriveMessages()`（index.ts）从 surface 投影出 `RequestMessage[]`；`toolHistory()` 供工具历史；`requestHeader()` 供配置种子。
- **恢复**：`Session.fromRestore()` 校验 envelope、seq 从 0 连续、surface 转换与 seed 相同的不变量；对独占/深冻值免拷贝免冻结。物理扫描与格式迁移见 [10-会话管理](10-会话管理.md)。
- **崩溃前已开始未结算的流**：不留 durable attempt 流（设计决策 v2-embedded-assistant-streams）——已送达前缀由 `interrupted: true` 的 assistant/message 定稿。

## 6. ignorable 契约：词汇如何增长而不 bump 版本

`SessionEvent.ignorable`（types.ts）：默认事件是"必需"的——读者遇到不认识的必需事件必须**拒绝重建**而非静默丢弃（fail-closed，存储侧对应 `validateStoredEvents`）；纯信息性记录才可标 `ignorable: true`。因此新增普通事件类型不 bump `SESSION_FORMAT_VERSION`，只有结构性变化（header 形状、envelope、核心事件语义、surface 机制）才 bump。

## 7. session-query：统一读模型

[packages/session-query/](../packages/session-query/README.md) 四包：

| 包 | 职责 |
|---|---|
| session-query（`ctx.sessionQuery`） | 抽象 `SessionQueryEngine`：`observeSession`（一次原子观察）、`searchSessions/searchEvents`（后端实现全文）、`listSessions`、`readSession`（完整重放验证）；类型含 `SessionLineageTrace`（fork 祖先/后代树）与 `SessionEventTrace`（事件被谁替换/引用/派生） |
| session-query-sqlite | 可丢弃的派生全文读模型（SQLite FTS5）；schema 版本不匹配**原地重置**（派生索引可重建，与会话日志不可变策略刻意对照） |
| tool-session-query | 模型侧工具 `session_search` / `session_trace` 等 |
| session-log-export | 导出 ZIP 归档：根 log 规范名、子代理 `subagents/<id>/`、图片按内容寻址 `media/` |

## 8. 设计收益

把日志定为唯一事实源，直接买到：

1. **可重放**：任何历史请求逐字节重建（测试快照体系建立在此之上）。
2. **免费 fork/resume**：都是日志操作（见 [10 章](10-会话管理.md)）。
3. **免费 transcript/UI**：人类视图 = `isAppendSurfaceEvent` 过滤的追加事件；压缩不删人类历史。
4. **免费遥测/统计**：token-meter、session-stats 都从日志重放。
5. **模型行为可审计**：`request/header` + `request/context` 记录每次路由决策的证据。
