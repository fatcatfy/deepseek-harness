# 07 事件驱动 —— Cordis 事件与扩展点

> 官方参考：[../docs/cordis-primer.md](../docs/cordis-primer.md)、[../docs/event-producer-consumer.md](../docs/event-producer-consumer.md)（生成的事件矩阵）、教程 [../docs/cordis-tutorial/](../docs/cordis-tutorial/index.md) 第 4 章

## 1. Cordis 事件模型

事件系统定义于 vendored [vendor/cordis/src/events.ts](../vendor/cordis/src/events.ts)。**dispatch 模式是事件公开契约的一部分**，新事件用 `@mode` JSDoc 标注（生成目录据此校验声明与 dispatch 一致）：

| 模式 | Awaited? | 顺序 | 返回值 | 典型用途 |
|---|---|---|---|---|
| `emit` | 否 | 注册序 | 无 | 观察（`agent/status`） |
| `waterfall` | 否 | 注册序 | 有 | around-中间件（`tools/execute`） |
| `parallel` | 是 | 并发 | 无 | 扇出（`session/flush`） |
| `serial` | 是 | 注册序 | 有 | 顺序决策（`agent/turn-stopping`） |
| `bail` | 否 | 注册序直到 bail | 有 | 首个有效值短路 |

### waterfall 语义（最容易踩坑的一种）

`ctx.waterfall` 是 **around-middleware**：监听器收到 `(...args, next)`；调 `next()` 把（可能已包装的）结果委托给下一层；**不调 `next()` 即否决剩余链条（含内建行为）**；返回值经 `next()` 传播。

- 协作型监听器通常改共享请求/决策对象后委托；也可整体替换结果，下游只见替换后的。
- 单决策事件里短路是设计：策略监听器拥有决策时可不调 `next()`；只注解/观察的监听器必须委托。
- `prepend: true` 仅当必须先于普通注册运行时使用。
- 根 AGENTS.md 规则：**waterfall 监听器必须调 `next()`**，否则短接整链。

### 注册即效应

`ctx.on()` 就是 `EventsService.register()`，**监听器注册本身是 `ctx.fiber.effect()`**——随 fiber 卸载自动注销。`ctx.effect()` 的 disposer 逆序执行；重复调用 no-op；UNLOADING 期注册新效应抛 `INACTIVE_EFFECT`（vendored 加固）。这就是"Registrations are effects"规则：每个贡献（提示词段、工具 schema、适配器、监听器）都经 `ctx.effect()` / `ctx.on()` 安装，重载与拆除可预测地展开。

## 2. DSH 的三个事件域

选对域是大多数改动的第一个决策（[architecture.md](../docs/architecture.md)）：

| 域 | 载体 | 用途 | 例 |
|---|---|---|---|
| **Session 事件**（durable） | append-only 日志 + `session/event` 广播 | 事实必须活过重载 | `turn/*`、`user/message`、`tool/*` |
| **Agent 事件**（live） | `agent/*`，携带活动 Agent | 观察/拦截进行中的工作 | `agent/pre-step`、`agent/request`、`agent/assistant-stream` |
| **Capability 事件** | 挂在接缝上 | 给能力加策略/适配器，不 import 循环 | `tools/*`、`fs/*`、`llm/stream`、`telemetry/*` |

每个事件谁生产、谁消费、什么模式——查生成的 [event-producer-consumer.md](../docs/event-producer-consumer.md)，不要背。

## 3. 声明形态

类型化事件经 TypeScript declaration merging 声明：

```ts
declare module '@deepseek-ai/cordis' {
  interface Events {
    /** @mode waterfall */
    'agent/pre-step'(...args: [...]): Promise<PreStepDecision>;
  }
}
```

仓库规约：事件 JSDoc 需要 `@mode` 与载荷 `@param`；`SessionEventMap` 成员默认 required-on-read（不认识就拒绝重建），纯信息性事件才带 `ignorable: true`（见 [06 章 §6](06-消息系统.md)）。

## 4. scope 过滤分发

[dsh-scope](../packages/core/scope/) 提供 per-agent 作用域原语（`createScope` / `scopeTarget`）：子代理只见自己的事件；父 scope 链上的监听器能看见后代。实现基于 Cordis 的 Context filter——同一进程内多个 Agent 各自的插件注册互不串扰，这是 agent preset（见 [11 章](11-扩展系统.md)）的运行时基础。

## 5. 实战：拦截请求、工具、turn

| 目标 | 事件 | 模式 | 现成范例 |
|---|---|---|---|
| 换 provider/model | `agent/request` | waterfall | model-selection 插件 |
| 接管失败重试 | `agent/request-error` | waterfall（返回 `{kind:'retry'}`） | [llm-retry](../packages/llm/llm-retry/src/index.ts) |
| 拒绝/改写进入消息 | `agent/pre-step` | waterfall | plan-mode、compaction-basic |
| 工具审批/沙箱 | `tools/pre-execute` | waterfall（allow/deny/cancel/ask） | approval、sandbox-policy |
| 包装工具执行 | `tools/execute` | waterfall | timeout-policy、指标 |
| 改工具结果 | `tools/post-execute` | waterfall（accept/block） | spill-policy、repeat-tool-reminder |
| 拦截模型流 | `llm/stream` | waterfall（只读） | session-checkpoint-policy |
| 阻止 turn 关闭 | `agent/turn-stopping` | serial（可 steer 续命） | goal-round-driver、hooks 桥 |
| 观察 UI 流 | `agent/assistant-stream` | emit | Web Session-follow 适配器 |

**选择原则**（cordis-primer）：事件用于拦截与策略；服务方法用于直接能力调用。把行为封装进插件——工具管线事件属于 `ctx.tools`，模型流属于 `ctx.llm`，live 协调属于 `ctx.agents`。
