## 2. 物理布局（JSONL 后端）

```
<root>/<projectKey(cwd)>/<encodeSegment(sessionId)>/session.vN.jsonl[.zstd]
```

- v0 文件名 `session.jsonl[.zstd]`；v1+ 为 `session.vN.jsonl[.zstd]`。
- 默认物理编码 zstd；`Config.root` 必填无默认。
- `encodeSegment`：SessionId 是 branded string，必须做单射路径段编码（`~XXXX` 转义，防 `../` 遍历）；`projectKey` 把 cwd 变成人类可读目录。
- 首行 header（`HeaderLine`）：`type:'session'`、`version`、`id`、`createdAt`、`cwd?`、`parentSession?`、`isSeeded`、`origin?:'subagent'`、`delegationDepth`、`agentPreset?`。**继承切割长度不在 header**——由最后一个带 `inherited:true` 的 `session/end-seed` 事件承载。

一行事件的样例形态：

```json
{"type":"user/message","seq":1,"time":3,"data":{...},"surfaceOp":"append"}
```

写入路径：每 handle 变更串行化在 promise 链上；live 路由事件进有界 write-behind buffer（200ms 批量）；`SessionWriteLease`（[lease.ts](../packages/session/session-persistence-jsonl/src/lease.ts)）是会话目录内的**跨进程写锁**；撕裂尾帧在首次新 append 前截断。Handle 契约：`append` 是 best-effort，`flush` 才承诺崩溃存活（见 [06 章 §4](06-消息系统.md) 的 checkpoint 策略）。

## 3. 版本机制：SESSION_FORMAT_VERSION

`SESSION_FORMAT_VERSION = 4`（[types.ts](../packages/core/session/src/types.ts)）。规则：

- 单调整数；由**写者产出什么**决定，不由"新读者能接受什么"决定。
- 只有**结构性变化**才 bump：header 形状、事件 envelope、核心事件语义、surface 机制（`SurfaceEventType` 集合与 `SurfaceOp` 变体）。新增普通事件不 bump（靠 `ignorable`，见 [06 章 §6](06-消息系统.md)）。
- 读者遇到未来版本：`refuseForeignFormatVersion` 转为 `SessionFormatUnsupportedError`（提示"升级 harness"而非"文件损坏"）。

## 4. 相邻迁移（adjacent migration）

核心规则——**已提交的 generation 不可变**：

- 迁移从不移动/覆盖/删除已提交代；只写最终目标的版本命名后继（如 `session.v4.jsonl.zstd`）；中间版本仅存在于流式 Stage 状态（v0 的 914 万展开事件无需物化即被 v1→v2 折叠为 7.3 万）。
- **读 open 不发布**：直接消费内存中的迁移结果。**写 open**：先编码 → Worker 验证（最多 2 个全代验证 Worker）→ 独占发布后继（POSIX 硬链接 + 目录 sync；Windows `MoveFileExW` no-overwrite）。
- 每条边（`vN→vN+1`）是有状态 Stage（`transformEvent/transformRun/finish`），由独立的包拥有；**不承诺降级**——保留低版本仅供检查。
- header-only `stat`/`list` 翻译受支持的历史 header 而不读 body、不发布后继。
- v3→v4 的 parent catalog completion 需要子会话证据，子会话失败被隔离不阻塞父历史。

SQLite 的对照：非会话数据（storage 组）与查询索引（session-query-sqlite）用单调 `SCHEMA_VERSION`，不匹配**原地重置**——派生数据可丢弃重建；会话日志则必须相邻迁移。两种策略刻意相反。

## 5. 恢复流程

```
物理扫描 SessionLogScanner（buffer 找换行，只解码完整记录；
  strict | recoverable 两种策略，recoverable 返回安全截断偏移）
  → sessionFormatCatalog.createRestore() 组装解码器 + 相邻迁移链
  → 逐事件流过 v0→v1→…→v3→v4 Stage → current collector
  → 逻辑校验（关系断言 + artifact 恢复）
  → Session.fromRestore()（校验 envelope、seq 连续、surface 不变量）
  → deriveMessages() 派生模型历史
```

崩溃恢复：`interruptedTurnClosers()` 为中断的尾部 turn 合成缺失工具结果 + `turn/end {kind:'interrupted'}`（见 [03 章 §6](03-Agent-Loop.md)）；迁移只为"有界的已发布重启"补缺失的 `turn/end`。

## 6. 分叉（fork）

实现集中在 core/session：

- **入口**：`SessionStore.fork(source, boundary?, childSessionId?)`——source 可为 live Session 或 SessionId；`boundary` 是 **inclusive** 源事件 seq（省略 = 最后事件；空源 fork 空子）。错误码：`SESSION_NOT_FOUND` / `SESSION_NOT_LIVE` / `SESSION_ALREADY_EXISTS` / `INVALID_BOUNDARY`。
- **种子构造** `buildForkSeed(events, boundary)`（[fork.ts](../packages/core/session/src/fork.ts)）：
  1. 复制 inclusive 前缀；
  2. 追加 `{type:'session/end-seed', data:{inherited:true}}`——fresh fork child 恒有带标记切割点；
  3. `openTurnClosers(prefix, {kind:'forked'})` 为边界处未闭合的 turn 合成工具结果与关闭器——`forked` 这个 TurnEndReason **只有 fork 种子携带，loop 从不发出**。
- `inheritedEventCount = boundary + 1`——只计复制的源事件，不含合成关闭器；`Session.isOwnSeq()` / `ownEvents()` 区分本会话与继承事件。
- 已关闭的 step/turn 原样保留（含已缺失结果的失败工具调用）。
- 子代理体系经 `meta.origin:'subagent'` + `delegationDepth` 建立持久血统——重启后递归预算不重置（见 [03 章](03-Agent-Loop.md) 与 subagent 文档）。

官方 fork 入口（architecture.md）：`ctx.agents.create({ sessionId, seed, meta: { parentSession, seedLength } })`——只有 agent-loop 发布的会话才持久化。

## 7. 投影（session-projection）

`ctx.sessionProjections`（[session-projection](../packages/session/session-projection/)）：注册的投影单元**增量 fold 已提交事件**；host 消费者用 `stateOf()` 读一个类型化状态；carriers 用 `snapshot()` 批量裁剪客户端视图。它是 todo 列表、goal 状态、收件箱、turn 边界、重试状态等"当前值"的统一来源——都从日志派生，因此重启后免费重建。[session-projection-cache](../packages/session/session-projection-cache/) 把投影检查点持久化以加速冷读。host 读者要么在激活期 require 该服务，要么显式失败——不允许静默默认。
