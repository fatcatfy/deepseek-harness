# 11 扩展系统 —— 配置即组合

> 官方参考：[../docs/architecture.md](../docs/architecture.md) 的 Profiles and bundles、[../apps/cli/README.md](../apps/cli/README.md)、[../packages/preset/README.md](../packages/preset/README.md)、patch 方言参考 [../packages/preset/agent-preset/skills/cordis-composition-reference/SKILL.md](../packages/preset/agent-preset/skills/cordis-composition-reference/SKILL.md)

## 1. 组合模型：没有特权核心

Cordis 基础（详见 [07 章](07-事件驱动.md)）：插件贡献服务、类型化事件、可逆效应到共享 Context；`Context` 运行时是 Proxy，属性读取走服务解析；服务经声明合并占据 `ctx.<key>`（如 `ctx.tools`、`ctx.llm`）。

DSH 在其上建立的核心思想是：**运行中的 dsh 是一棵从有序层组合出的插件树**——

```
空根（profile/cordis.yml = "[]"）
 → 各 bundle 的 cordis.patch.yml（按 dsh.profile.bundles 顺序）
 → profile 自己的 cordis.patch.yml（$DSH_HOME/profiles/<name>/）
 → home 层（$DSH_HOME/cordis.patch.yml，机器级偏好）
 → --patch overlays（argv 顺序，最高优先）
```

## 2. 三个组合单位

| 单位 | 是什么 | 声明位置 |
|---|---|---|
| **profile** | 命名的进程组合（web/headless/sdk/sdk-minimal/acp 模板；desktop 名字保留给 Electron） | `$DSH_HOME/profiles/<name>/package.json` 的 `dsh.profile.bundles`（有序） |
| **bundle** | Cordis 配置行 + 所挂代码的可分发 npm 包 | 包 `package.json` 的 `dsh.bundle.patch`（字符串或有序数组，指向 patch 文件） |
| **agent preset** | 每 Agent（会话）的能力集 | bundle patch 里的 `preset-<id>` 行，`config.plugins` 是完整 entry 列表 |

bundle 家族（[packages/bundle/](../packages/bundle/README.md)）：

- **dsh-base**：web/headless/sdk/acp 的共享第一层——模型适配器、工具、持久化、沙箱与审批、设置、凭据、遥测（约 130 行组合）
- **dsh-web-app**：加浏览器应用（host 行 + 浏览器 roster + 把 base 的 agent 面行逐 id 禁用后插入 preset registry）
- **dsh-headless**：一次性运行器，无服务器
- **dsh-sdk-app** / **dsh-acp-app**：JSON-RPC / ACP 服务器
- **dsh-sdk-minimal**：**唯一不经 dsh-base 的完整独立树**（deliberate exception）

## 3. patch 方言（cordis.patch.yml）

- 顶层是 PatchOptions 数组：`insert: [rows]` 追加行；带 `id` 的条目定向既有行——提供的字段**整体替换**（`config` 不深合并，需重述全部保留字段）；truthy `name` 是对既有插件名的断言。
- 行字段：`id` / `name`（插件包名）/ `config` / `disabled` / `inject` / `intercept` / `isolate`；`group: true` + `name: cordis:group` 使 config 成为嵌套 entry 列表；`cordis:include` 从 `config.path` 载入字面列表。
- **`!!js` 只允许两处**：`config`（该行声明注入激活后、对该插件 ctx 求值——所以 `!!js ctx.webStartup.host` 合法）与 `disabled`（对 loader ctx、每次挂载决策）；其余元数据（id/name/group/inject/intercept/isolate）必须字面量——`verify-cordis-config` 静态门禁强制（元数据里的 `!!js` 会保持真值数据并静默改变组合，故拒绝）。
- "禁用而非删除"：共享 base 之上的层用 `disabled: true` 关行而不是删行——删除会让未来重排组合时静默复活。
- 无目标的 patch 警告跳过（允许一个共享 overlay 不必匹配每棵树）；**存在但不可解析的 patch 文件必须抛错**（misconfiguration fails loud）。

## 4. 启动链路

```
apps/cli/src/bin.ts (runCli)
  → args.ts (parseDshArgs：launcher 只解析 --profile/--patch/--dump-config*；
              其余参数原样交给树内插件的 ctx.cmdlineArgs)
  → profile-boot.ts (runProfile：装环境代理 → composeProfile 计算不可变 runtime resolution
                      → boot())
  → boot() [packages/boot/app-boot/src/index.ts]
      new Context() → ctx.plugin(Loader) → mountRootInclude()
      （构造根 Include entry：config.path 指向空 root，patches = 全部层）
  → Loader 按行 import 插件包、挂 fiber、服务可用性驱动激活顺序
  → auditStartupEntries（必需 id 校验：agent-loop、webserver、modules、connection…）
```

**bare 插件名解析**：profile 目录的 node_modules 被装进 Node 的 ESM/CJS 内部解析器拦截层；`createRuntimeResolution()` 从安装 anchor BFS `dependencies` + `peerDependencies` 产出冻结的解析表。静态对应物 `verify-cordis-config.ts` 校验每个 `cordis.yml` 里的 bare 名都出现在正确 manifest 的 `dependencies` 中（还校验 preset 平面分离、client halves 声明一致、source-plane 解析到 `.ts` 源）。

## 5. HMR：活着的重排

[packages/boot/hmr/](../packages/boot/hmr/)（`dsh-hmr`）把**模块替换、Include 刷新、profile 配置变更**放进同一个串行队列（`runExclusive()` 拒绝嵌套事务）。base 默认只开配置热重载（`root: []`）；模块 watch 需在 profile patch 显式配置；headless/SDK/ACP 禁用。配合"注册即效应"，整棵树可以活着重排而可预测地展开。

## 6. Agent preset：每会话的能力集

与 profile 的根本区别：profile 决定**进程**挂什么；preset 决定**每个 Agent（会话）**看到什么。

实现（[packages/preset/](../packages/preset/README.md)）：

- `AgentPreset`（声明行插件）→ `AgentPresetRegistry`（`ctx.agentPresets`）急切 `activate()`：`createScope` + `mountPreset` 在**独立 scope + 内存 Loader 树**中挂载 `config.plugins`。
- **isolate realm 强制**：`leakedServices()` 扫描挂载子树——任何泄漏进 root realm 的服务抛错；preset 内提供服务者必须用 `cordis:group` + `isolate: {<service>: true}` 把 provider 与全部 consumer 放进同一 realm。
- 会话记录 preset id，重启后按 id 取当前定义；Generation 管理 revision 保留（多个会话可钉在不同 revision）。
- Host 进程共享一个 Agent loop；每个 Agent 只看到自己选中 revision 的 tools/prompts/skills。

shipped Web presets（[packages/bundle/web-app/presets/](../packages/bundle/web-app/presets/)）：`standard`（全能力）、`ptc`（run_code 形态）、`minimal`（仅 persona + persistent shell）、`cordis`（面向插件开发，带 tool-cordis 与 creator skills 路由）。

## 7. 运行时自修改（extensions 组）

[packages/extensions/](../packages/extensions/README.md)——让模型**在会话内**定义和运行动态插件，但有明确信任立场：

- `tool-cordis`：只读发现工具（`cordis_inspect_list/query`）。
- `cordis-host-runner`（`ctx.dynamicCordisRunner`）：动词 define → run → stop → undefine；`node:vm` 沙盒执行（**vm 隔离不是安全边界**——Node globals 缺席或重定向到 Cordis 服务；"把动态包当作 bash 访问对待"）；有浏览器半时 run 需人在 `cordis/request-run` 批准。
- 定义是 **session-scoped + 进程本地**：其他会话读不到、重启清空、历史日志只留参数与回执。持久安装一律走 Plugin Manager（`dsh plugin`）；**没有任何模型工具能创建持久插件**。

## 8. Plugin Manager 与外部分发

[packages/boot/plugin-manager/](../packages/boot/plugin-manager/)：`dsh plugin --profile <name> <pnpm args>` 与模型工具 `plugin_manager` 共享操作层（list/install/remove bundles、版本兼容豁免需 `acceptRisk: true`）。bundle 是唯一能通过该命令激活 profile 层的包形态——插件以 `cordis.yml` 行挂载，库只是依赖（分类判据见 [dsh-doc 技能](../.agents/skills/dsh-doc/SKILL.md) 的 fact-check 节）。

## 9. 外部工具与桥

- **MCP**（[packages/mcp/](../packages/mcp/README.md)）：每 MCP 服务器一个 entry（stdio / streamable-http）；工具以 `mcp__<server>__<tool>` 稳定限定名注册进 `ctx.tools`；重连退避 500ms→30s。
- **Hooks 桥**（[packages/hooks/](../packages/hooks/README.md)）：复用现存 Claude Code / Codex 的 `hooks.json`——仅 command hook 运行；**exit 2 = 阻断**并展示 stderr 为原因；可附加模型可见上下文。

## 10. 用户态：settings / credentials / identity

- [settings](../packages/settings/settings/)（`ctx.settings`）：从每个插件 Config schema 派生活配置表单；编辑持久化到活动 profile patch 并立即应用；volatile 字段更新不 remount。
- [credentials](../packages/credentials/)：配置**命名**凭据引用而非内嵌值（`apiKeyEnv` 等）；本机存储在私有 `$DSH_HOME/.credentials.yaml`，环境变量覆盖优先。
- [identity](../packages/identity/anonymous-user-id/)：每 harness home 一个匿名 UUID（删除文件即重置），供遥测/反馈携带——零配置且可重置。
