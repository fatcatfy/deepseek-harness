# 01 架构总览

> 对应官方文档：[../docs/architecture.md](../docs/architecture.md)（改 `packages/` 前的必读总纲）

## 1. 项目定位

DeepSeek Harness（`dsh`）是一个 **agent harness**：它围绕"模型 + 工具 + 会话"构建完整的智能体运行时，提供从 CLI、Web UI、桌面应用到 SDK 的多形态产品面。它的两个根本设计决定了一切代码的组织方式：

1. **全插件架构**：基于 vendored 的 [Cordis](../docs/cordis-primer.md) 框架，模型适配器、工具注册表、会话日志、Agent 循环本身都是插件树上的普通节点。没有可打补丁的特权核心——扩展 DSH 的方式是"在旁边挂一个插件"，而不是"改它"。
2. **会话日志即真相源**：一切模型可见的内容（system prompt、用户消息、工具结果、压缩摘要）都必须是会话日志里的持久事件，任意模型请求都能从日志完整重建（"Model-visible means logged"）。

## 2. 分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│ 产品面    CLI(dsh)  │  Web(浏览器)  │  Desktop(Electron)  │  TS/Python SDK  │  ACP  │
├─────────────────────────────────────────────────────────────────┤
│ Remote 层  api/gateway(JSON-RPC/WS 多路复用) · api/*-controller   │
│            client/*(浏览器半边, 60+ 包) · host/*(服务器半边)        │
├─────────────────────────────────────────────────────────────────┤
│ Agent 内核  core/agent(契约) · core/agent-loop(驱动器)             │
│            core/session(日志+Store) · core/tools(注册表+管线)     │
│            core/system-prompt · core/scope · llm/llm(适配器接缝)  │
├─────────────────────────────────────────────────────────────────┤
│ 能力层     shell/fs/web/lsp/browser-use/computer-use(工具族)      │
│            compaction/spill/context(上下文治理) · subagent(委派)  │
│            sandbox/approval/permission(安全) · jobs/schedule/...  │
├─────────────────────────────────────────────────────────────────┤
│ 组合层     bundle/*(dsh-base 等 6 个 bundle) · preset/*(每会话能力)│
│            boot/app-boot(profile→插件树) · extensions(运行时自修改)│
├─────────────────────────────────────────────────────────────────┤
│ 框架层     vendor/cordis(Context/Service/事件/effect)             │
│            vendor/loader · include · schemastery(配置组合)        │
└─────────────────────────────────────────────────────────────────┘
```

一次 `dsh web` 启动就是一次"组合"：空根配置 → 按 profile 列出的 bundle 逐层应用 patch → profile 用户补丁 → home 级补丁 → `--patch` 覆盖，最终得到一棵可运行的插件树。详见 [11-扩展系统](11-扩展系统.md)。

## 3. 核心概念速览

| 概念 | 一句话解释 | 权威定义 |
|---|---|---|
| Cordis | 底层插件框架：插件贡献服务、类型化事件、可逆效应到共享 Context | [../docs/cordis-primer.md](../docs/cordis-primer.md) |
| profile | 命名的进程组合（web/headless/sdk/sdk-minimal/acp），存于 `$DSH_HOME/profiles/<name>` | [../packages/boot/app-boot/src/profile.ts](../packages/boot/app-boot/src/profile.ts) |
| bundle | Cordis 配置行 + 所挂代码的可分发格式（npm 包 + `cordis.patch.yml`） | [../packages/bundle/](../packages/bundle/README.md) |
| agent preset | 每 Agent（会话）的能力集，在独立 scope + 内存 Loader 树中挂载 | [../packages/preset/](../packages/preset/README.md) |
| Session log | append-only 的事件日志，模型历史的唯一来源 | [../packages/core/session/](../packages/core/session/README.md) |
| Agent loop | 驱动"模型请求→工具执行→再请求"的默认驱动器 | [../packages/core/agent-loop/](../packages/core/agent-loop/README.md) |
| capability seam | 可替换能力，含 Service Definition / Provider / Consumer 三角色 | [../docs/glossary.md](../docs/glossary.md) |
| step / turn | step = 一次模型请求 + 其工具调用；turn = 零或多个 step | [../docs/architecture.md](../docs/architecture.md) |

## 4. 包布局与模块职责

monorepo 位于 `packages/<group>/<pkg>/`，包名 `@deepseek-ai/dsh-<name>`。分组职责（详见 [../packages/README.md](../packages/README.md)）：

| 组 | 职责 | 代表包 |
|---|---|---|
| `core/` | Agent 内核：契约 + 默认实现 | agent、agent-loop、session、tools、system-prompt、scope |
| `llm/` | 模型调用 | llm（接缝）、llm-deepseek、llm-pi-ai、llm-retry、token-meter |
| `shell/` `fs/` `web/` `lsp/` | 模型可见工具族（每族 = 定义 + provider + 工具） | shell、bash-sandbox、tool-bash；fs-local；web-search-* |
| `subprocess/` `terminal/` `ssh/` `ptc-runtime/` | 进程/终端执行底座 | subprocess、terminal(pty)、ptc-runtime |
| `sandbox/` | 进程约束 | sandbox、sandbox-policy |
| `compaction/` `context/` `spill/` | 上下文治理 | compaction-basic、agent-instructions、spill-policy |
| `session/` | 会话持久化家族 | session-persistence-jsonl、session-format-*、session-query、session-title |
| `subagent/` | 委派代理 | subagent(spawn/fork/acp/dsh-sdk/codex/claude-code)、tool-subagent |
| `boot/` | 启动与组合 | app-boot、plugin-manager、hmr、cmdline、config-editor |
| `bundle/` | 6 个组合 bundle | base、web-app、headless、sdk-app、acp-app、sdk-minimal |
| `preset/` | 每会话能力集 | agent-preset、agent-preset-registry、persona |
| `extensions/` | 运行时自修改 | tool-cordis、cordis-host-runner |
| `skill/` `mcp/` `hooks/` | 技能 / 外部工具 / 桥 | skill-filesystem、mcp-client、hooks-claude-code |
| `api/` | Remote BFF 层 | gateway、session-controller、settings-controller |
| `host/` `client/` | Web 的服务器/浏览器半边 | webserver、frontend-static；web、ui-conversation、ui-chat |
| `sdk/` | TypeScript SDK | protocol、client(DeepSeekHarness)、server(JSON-RPC) |
| `acp/` | automation-only ACP 服务器 | acp |
| `interaction/` `feedback/` `goal/` `todo/` `plan/` | 人机交互与任务结构 | commands、user-approval；plan-mode、goal-round-driver |
| `jobs/` `schedule/` `workflow/` `webhook/` | 后台任务生态 | jobs-local、schedule、workflow-ptc、webhook |

顶层目录：`apps/`（cli=dsh 本体、web=Vite 前端、desktop=Electron 壳）、`python/`（Python SDK + 运行时 wheel）、`native/`（node-addon-system）、`vendor/`（vendored Cordis，已改作用域 `@deepseek-ai/*`，见 [../docs/rescope.md](../docs/rescope.md)）、`docs/`、`website/`（VitePress 投影）、`benchmarks/`、`scripts/`（门禁与生成器）、`snapshots/`（录制会话快照）。

## 5. 依赖关系

- **框架依赖**：所有 harness 包通过 peerDependencies/devDependencies 声明 `@deepseek-ai/cordis`；vendored 包用 `workspace:~`，DSH 包用 `workspace:*`（规则见 [../.agents/notes/implemented/process/2026-08-10-npm-release-sequences.md](../.agents/notes/implemented/process/2026-08-10-npm-release-sequences.md)）。
- **包间依赖的真实地图**是生成物：[../docs/module-graph.md](../docs/module-graph.md)（`pnpm run doc-sync` 再生成）。
- **依赖方向的经验法则**：
  - `core/*` 互相依赖但都只依赖契约（`dsh-agent` 声明事件与接口，`dsh-agent-loop` 实现）
  - 工具族（shell/fs/web）依赖 `core/tools` 与 `core/agent` 的接缝，不依赖 `agent-loop`
  - 约一半子系统是**循环事件的纯消费者**（llm-retry、compaction-basic、plan-mode、goal-round-driver……），它们不 import 循环代码
  - 产品面（client/host/api/sdk）只经 Remote/服务面消费内核，绝不直接触内核内部
- **静态强制**：`scripts/package-graph.ts`、`verify-package-dependencies.ts`、`verify-runtime-closure.ts` 等门禁在 CI 校验依赖合法性；`verify-cordis-config.ts` 强制 `cordis.yml` 里的 bare 插件名必须出现在对应 manifest 的 `dependencies` 中。

## 6. 运行方式

### 6.1 环境与安装

```sh
# Node ^22.19 || >=24，pnpm workspaces
pnpm install
```

真实模型调用需要 `DEEPSEEK_API_KEY`（可选 `DEEPSEEK_BASE_URL`），读取根目录 `.env`。

### 6.2 日常命令（真源是 [../package.json](../package.json)，Makefile 只是别名）

| 命令 | 作用 |
|---|---|
| `pnpm dsh --profile headless "task"` | 从源码跑一次性任务（tsx ESM hook 启动） |
| `pnpm run start:web` / `make web` | 启动 Web（默认 3080 端口） |
| `pnpm run dev:web` | 完整 Web 开发循环：build → 3 个 watcher → serve |
| `pnpm run dev:desktop` / `start:desktop` | Electron 桌面应用（先准备打包运行时） |
| `pnpm run build` | 双编译面：Host(`tsc -b tsconfig.host.json`+tsdown) 与 Client |
| `pnpm run test` / `test:coverage` | 单元测试 / CI 覆盖门禁（per-file 100%） |
| `pnpm run test:e2e` | 真 API 测试（无 key 自跳过） |
| `pnpm run test:snapshot` | 录制会话重放（keyless） |
| `pnpm run typecheck` / `lint` / `duplication` / `hygiene` | 质量门禁 |
| `pnpm run doc-sync` / `test:docs` | 文档门禁 |
| `pnpm run website:build` | VitePress 站点（兼死链检查） |
| `pnpm run demo:ptc -- "task"` | headless PTC 模式演示 |

### 6.3 五种 profile 与启动链路

```
dsh --profile <name> / dsh <name>
  web          = dsh-base + dsh-web-app（浏览器应用）
  headless     = dsh-base + dsh-headless（一次性运行器，无服务器）
  sdk          = dsh-base + dsh-sdk-app（JSON-RPC stdio 服务器）
  sdk-minimal  = dsh-sdk-minimal（唯一不经 dsh-base 的独立树）
  acp          = dsh-base + dsh-acp-app（automation-only ACP 服务器）
```

启动链路：`apps/cli/src/bin.ts`(`runCli`) → `args.ts`(`parseDshArgs`，只解析 launcher flag，其余参数原样交给树内插件) → `profile-boot.ts`(`runProfile`) → `boot()`([../packages/boot/app-boot/src/index.ts](../packages/boot/app-boot/src/index.ts)) → 挂载根 Include → Loader 按行激活插件 → `auditStartupEntries` 校验必需条目。

**只有 `dsh` profile 是受支持的 Node 应用启动方式**；`verify-application-entrypoints` 门禁拒绝任何绕过 `dsh` 的 Node 应用路径（规则见 [../docs/architecture.md](../docs/architecture.md) 的 Application launch 节）。

查看机器实际启动的插件树：

```sh
dsh --profile web --dump-config        # 输出可加载的 YAML，含每层来源注释
dsh --profile web --dump-config-schema # JSON Schema 2020-12
```

## 7. 一条消息的旅程（数据流总览）

```
用户输入(followup) ──▶ 收件箱(持久事件 agent/inbox/spliced)
   │
   ▼
turn/start ──▶ 认领取户箱消息 + 组装 system prompt + 工具 schema
   │            └─ agent/pre-step waterfall（插件可拒绝/改写）
   ▼
step/start ──▶ agent/request waterfall ─▶ llm.prepareCall（绑定适配器代）
   │          system/message + user/message + request/header 落日志
   │          deriveMessages() 从日志派生模型历史 → 冻结请求
   ▼
llm.stream(请求) ──流式──▶ assistant/message（内嵌完整流）落日志
   │
   ├─ 无工具调用 ──────────────▶ turn 收束（agent/turn-stopping → turn/end）
   └─ 有工具调用 ─▶ tool/call 落日志
        └─ tools/pre-execute(审批/沙箱) → tools/execute(工具体)
             → tools/post-execute → tool/result 落日志
             └─ tools 还欠答复 ─▶ 下一个 step（回到 step/start）
```

这条主干会在后续章节展开：循环细节见 [03](03-Agent-Loop.md)，模型调用见 [04](04-模型调用-dsh-llm.md)，工具见 [05](05-工具系统.md)，日志与消息见 [06](06-消息系统.md)。
