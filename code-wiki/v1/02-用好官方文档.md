# 02 用好官方文档 —— 官方教你用 DeepSeek Harness

DSH 仓库自带一套分工严格、以生成为守卫的文档体系。理解它的分层，比死记任何一篇内容都重要：**每个事实只有一个家（one home per fact）**，找对了层级就找对了答案。

## 4. Agent Notes：决策考古

[../.agents/notes/](../.agents/notes/README.md) 是设计决策的最终归属。目录编码 `{lifecycle}/{class}/yyyy-mm-dd-topic.md`：

- `implemented/` —— 已发布决策的"为什么、放弃了什么、要求什么验证"（与代码同 PR 保持同步），如：
  - [2026-08-31-released-session-format-migrations.md](../.agents/notes/implemented/architecture/2026-08-31-released-session-format-migrations.md)（相邻迁移）
  - [2026-08-10-session-log-version-mechanism.md](../.agents/notes/implemented/architecture/2026-08-10-session-log-version-mechanism.md)（版本机制）
- `proposed/` —— 活跃提案；`rejected/` —— 只保留能阻止"有诱惑力的错误"的拒绝记录；`archived/` —— 冻结历史，**不是当前权威**。
- class 闭集：`feature` / `bug-fix` / `simplification` / `architecture` / `process` / `testing`。

写作门槛：只有代码/测试/现有文档解释不了的**持久决策理由**才值得写；机械修改豁免。格式由 `verify-agent-note-format` 门禁强制。

## 5. 双语体系

- 每份在册文档是三件套：`foo.md`（英）+ `foo.zh.md`（中）+ `foo.i18n.yaml`（配对记录），同级存放，**没有 locale 目录**。
- 两种语言同等权威；改一侧必须在同一 PR 补另一侧并重记录（`pnpm run verify-translation-pairing --write <pair>`）。
- 生成区（如 subsystems 的 Cordis API 区）把生成数据写进两页同一 region，重生成无需手工中文。
- 完整契约：[../docs/i18n/README.md](../docs/i18n/README.md)；术语真源：[terminology.md](../docs/i18n/terminology.md)。

## 6. 文档网站

`website/` 是**投影不是副本**：[../website/docs.ts](../website/docs.ts) 是显式发布清单（allowlist），`scripts/project-doc-site.ts` 把规范源重写进可丢弃的 `website/.generated/` 树，VitePress 构建它。仓库 Markdown 永远是唯一可编辑源；每路由还输出 raw-Markdown 孪生（`URL+.md`）和根 `llms.txt` 索引，方便 agent 消费。

```sh
pnpm run website:build   # = docs:build，兼作死链检查
```

## 7. 维护者技能（.agents/skills/）

仓库为 agent 会话内置 16 个工作流技能，经 skill-filesystem 在仓库内会话中自动可见。常用的：

- `dsh-doc` / `dsh-prose-standard` —— 文档写作与散文标准
- `dsh-pre-push-checks` —— 推送前选择最小覆盖检查集
- `dsh-code-review` —— 本仓库的审查标准
- `dsh-create-upgrade-guide` —— 破坏性变更的升级指南
- `dsh-find-simplifications` / `dsh-speed-up-perf` / `dsh-trim-cot-leakage` —— 简化/性能/去推理泄漏

另有一组面向产品会话的 creator skills 在 [../packages/preset/agent-preset/skills/](../packages/preset/agent-preset/skills/)：`cordis-plugin-development`（含模板）、`cordis-composition-reference`（**Loader patch 方言参考**：insert / 按 id 覆盖 / group / disabled / `!!js` / isolate）等。

## 9. 实战技巧

- **"机器到底启动了什么"**：`dsh --profile web --dump-config` 输出带每层来源注释的 YAML；任何一行都可以被你自己的 patch 按 id 替换。
- **改配置前**查 [config-catalog.md](../docs/config-catalog.md)；**给模型加能力前**查 [tool-catalog.md](../docs/tool-catalog.md) 与 architecture.md 的 "Where new behavior goes" 表。
- **遇到行为不一致**先查 postmortem（可能是已知教训）与 Agent Notes（可能是刻意决策）。
- **文档有预算与 slop 检查**（`pnpm run test:docs`、`verify-doc-budgets`）：根 AGENTS.md ≤1960 词、architecture.md ≤2400 词等——所以根文档永远短而密，细节都在链接到的下层。别在根文档里找细节，顺着链接下钻。
