# 13 延伸话题 —— 工程、生态与二次开发

本章"自行发散"，收录跨领域主题与把前面十二章串起来的工程视角。

## 1. 测试体系（七层）

权威：[../docs/testing.md](../docs/testing.md)。命令与定位：

| 层 | 命令 | 定位 |
|---|---|---|
| 单元 | `pnpm run test` | 常规单测 |
| 覆盖门禁 | `pnpm run test:coverage` | **CI 用的是这个**（per-file 100% on `packages/*/*/src`） |
| 真 API e2e | `pnpm run test:e2e` | 需 `DEEPSEEK_API_KEY`，无 key 自跳过；官方政策"我们是 DeepSeek——不要吝啬真 API 测试" |
| owner-local 期望 | `pnpm run test:expected` | 进程期望，属主本地 |
| 会话快照 | `pnpm run test:snapshot` | **keyless** 录制会话重放（`snapshots/` 顶层树只收 session-driven 用例）；`:record` 重录 |
| Web 浏览器快照 | `pnpm run test:web` | 浏览器 e2e（picker 用 pin-browse-picker overlay） |
| 基准 | `pnpm run test:bench` | 性能门禁（[BENCHMARK.md](../BENCHMARK.md)） |

关键纪律：**每个非平凡的模型可见/产品可见变更都要更新一个 keyless 录制会话快照**；fixtures 在 macOS/Linux 重放——"fix fixtures, not normalizers"；Agent-loop、会话生命周期、`SessionEventMap` 的变更必须**同一 PR 更新 TS 与 Python SDK 的期望输出**（`pnpm run test` 不覆盖它们）。

## 2. 防御性模式

权威：[../docs/defensive-patterns.md](../docs/defensive-patterns.md)（写生命周期/并发/子进程/teardown 前必读）。核心条目：

- 独立报告正交结果（不要把多个信号折叠成一个布尔）
- 双边守公共契约（调用方与被调方各自校验边界）
- 异步态 ≠ 同步态（快照与 live 状态不混用）
- dispose 要到 quiescence（teardown 等待静止，见 Cordis fiber 的逆序 disposer）
- dispatcher 包住回调异常（一个监听器失败不拖垮 dispatch）
- 不可信输出不给环境变量 / 可预测路径

四个已付学费的真实教训在 [../docs/postmortem/](../docs/postmortem/README.md)（ACP 默认导出丢 inject、`!!js` 字面量永久禁用工具、Web agent 验证了错误的服务器、Landlock partial-notice 误分类）。

## 3. 安全模型

分层（base bundle 的"执行边界"段）：

```
sandbox（进程约束接缝）
  ├─ bash-sandbox / pwsh-sandbox（按平台）
  ├─ fs-sandbox（文件系统策略；读后才许写等观察策略）
  └─ sandbox-policy（mode: DSH_PERMISSION_MODE ?? 'workspace-write'）
approval（ctx.approval：tools/pre-execute 的 ask 决策 → 人类 allow/reject；
         无 answerer 时 fail-closed）
permission（三档 presets；permission-presets 捆绑成 UI 选择器）
credentials（命名引用而非内嵌值；authorization 走人类授权流）
```

其它安全面：Web 请求信任栏（loopback + Origin + token→签名 cookie，见 [12 章 §3.1](12-产品面.md)）；路径段编码防遍历（会话目录、spill）；子代理委派时**固化**沙箱模式并强制 `approvalPolicy:'never'` 不可再扩权；image/file 附件读时按 digest 校验（fail closed）；动态 Cordis 的 vm 沙盒**不是**安全边界。

## 4. 遥测与隐私

- `session-telemetry-otel` 默认 **FEEDBACK_ONLY** 模式（只有用户主动反馈时才携带数据）。
- `anonymous-user-id`：每 harness home 一个匿名 UUID，可删除文件重置。
- `message-feedback` 永不进模型历史或遥测；导出/展示前有 redact。
- DeepSeek 请求携带 `attributionHeaders()` 与匿名 id（作为 Resource `user.id`）。

## 6. typert：类型图与 RPC 契约

[typert](../packages/typert/) 是"类型图"基础设施：`@Remote` / `@RemoteScope` 标注 + 构建期生成 Host/Client 契约（`InvocationDescriptor`），支撑 api/gateway 的类型化调用与事件转发。`LlmRuntime` 继承 `TypertRemoteService` 即得益于此。文档：[../docs/api-gateway.md](../docs/api-gateway.md)。

## 7. 实验区与前瞻

- **Agent Teams**（[subsystems/agent-team](../docs/subsystems/agent-team.md)）：`ctx.agentTeams` 上的协调接缝——持久 roster、任务板、邮箱，叠在 continuable subagent 之上。
- **computer-use / browser-use**：独占命名 provider 注册（实验的 Playwright MCP / Chrome DevTools MCP / Stagehand 在 experimental 组）。
- experimental 组的定位：**默认公开、显式私有例外**。
- 活跃提案（`proposed/` notes）：session-capability-protocols、logical-session-storage-rebuild、composer-model-and-draft-editor 等——看 `proposed/` 是了解项目走向的最好方式。

## 8. 性能

[benchmarks/](../benchmarks/) + `vitest.bench.config.ts` 是性能门禁；`dsh-speed-up-perf` 技能规定"实测行为保持的修复"工作流。明显的设计性性能决策举例：会话恢复的流式迁移 Stage（不物化中间事件）、session-projection-cache 加速冷读、write-behind 批量落盘、压缩总结复用 provider KV cache。

## 9. 设计哲学十条（全仓库的共识）

1. **万物皆插件**：没有特权核心；行为长在扩展点上，不长在循环里。
2. **日志即真相**：model-visible ⟺ logged；fork/resume/UI/遥测全部派生。
3. **注册即效应**：`ctx.effect()` / `ctx.on()`，一切可逆、teardown 可预测。
4. **能力接缝三角色**：Service Definition / Provider / Consumer 同时设计才算完整。
5. **显式 resolve**：默认值是 owning implementation 的显式步骤，不是 `run()` 里的隐藏 `??`。
6. **配置失败要响**：能加载期发现就加载期抛；绝不静默跳过引用缺失。
7. **信任 TypeScript**：类型化同进程边界不加运行时校验；校验放在解析/配置/模型 JSON/持久化/进程/wire 边界。
8. **Source plane ≠ artifact plane**：静态门禁经 tsconfig paths 解析到 `src`；消费 built `lib/` 的门禁显式声明。
9. **一词一概念、一事实一家**：术语表管词；文档分层管事实归属；生成物管目录。
10. **对称性**：并行值的不对称通常暗示漏掉的抽象（见根 AGENTS.md "Prefer symmetry"）。

## 10. 二次开发指南

按改造目标给入口（详细步骤都在 cookbook）：

| 想做什么 | 路径 |
|---|---|
| 换/加模型 provider | 零代码：llm-pi-ai `providers` 配置；写适配器：[adding-an-llm-adapter](../docs/cookbook/adding-an-llm-adapter.md)（见 [04 章 §7](04-模型调用-dsh-llm.md)） |
| 加模型可见工具 | [adding-a-tool](../docs/cookbook/adding-a-tool.md)（定义→注册→presentCall/presentResult→快照，见 [05 章](05-工具系统.md)） |
| 加插件包 | [adding-a-package](../docs/cookbook/adding-a-package.md)（含 README 双语与 Model Experience 要求） |
| 给会话换能力集 | 组合 agent preset（[11 章 §6](11-扩展系统.md)）；预设行需要 isolate realm |
| 改部署行为 | cordis.yml config（查 [config-catalog](../docs/config-catalog.md)）；环境差异用 overlay 不用 if |
| 接外部系统 | webhook（触发会话）/ hooks 桥（复用 hooks.json）/ MCP（外部工具）/ ACP（程序驱动） |
| 嵌入自己的产品 | TS SDK（`DeepSeekHarness`）或 Python SDK；远端部署见 user/guide/public-deployments |
| 改持久化格式 | 先读 [session-format-status](../docs/session-format-status.md) 与 [reviewing-persistence-type-changes](../docs/cookbook/reviewing-persistence-type-changes.md)：结构性变化 bump 版本 + 相邻迁移包 + persistence-change 记录 + 快照 |

**提交前**：按 [dsh-pre-push-checks](../.agents/skills/dsh-pre-push-checks/SKILL.md) 选最小覆盖集（匹配证据到表面：行为测试/快照/doc-sync/构建冒烟/真 API e2e），不要反射性跑全量；外部可感知的破坏性变更立即写 upgrade guide。

## 11. 一页总结

```
DeepSeek Harness = Cordis 插件树（组合即配置）
                  + 会话日志（记忆即事件，模型可见即已日志）
                  + Agent Loop（turn/step 状态机，扩展点即事件）
                  + 能力接缝（tools/shell/fs/web/llm/subagent...）
                  + 上下文工程（system prompt / 注入 / skill 目录 / spill / 压缩）
                  + 五个产品面（CLI / Web / Desktop / TS+Py SDK / ACP）
                  + 一套工程纪律（测试七层 / 防御模式 / 文档分层 / 双语 / 门禁）
```

理解了这句话，就理解了这个仓库。
