# 05 工具系统 —— 能力接缝与执行管线

> 官方参考：[../packages/core/tools/](../packages/core/tools/README.md)、管线图 [../docs/tool-execution-pipeline.md](../docs/tool-execution-pipeline.md)、编写手册 [../docs/cookbook/adding-a-tool.md](../docs/cookbook/adding-a-tool.md)

## 1. 工具的定义与注册

### 1.1 ToolDefinition

[packages/core/tools/src/index.ts](../packages/core/tools/src/index.ts) 定义：

```ts
interface ToolDefinition extends ToolSchema {   // name/description/parameters/deferLoading?
  readonly output: ToolOutputDefinition         // { schema, render(args, value): ContentBlock[],
                                                //   presentationMeta?(args, value) }
  execute(args: unknown, exec: ToolRunContext): Promise<unknown>   // 只返回 canonical JSON 值
  timeoutMs?: number                            // 协作式超时（由 timeout-policy 守卫执行）
  isConcurrencySafe?(args): boolean             // 仅精确 true 才可并行
  presentCall?(args): ToolCallView              // UI 挂起态卡片（纯函数）
  presentResult?(args, result): ToolResultView  // UI 完成态卡片（纯函数）
}
```

### 1.2 类型化 DSL：defineTool

[schema.ts](../packages/core/tools/src/schema.ts) 的 `defineTool` 用参数/输出 schema DSL 推断 `InferArgs` / `InferValue` 类型；`validateArgs()` 在 execute 前校验模型参数（违规抛 `ToolArgsError` / `INVALID_ARGS`）。`presentCall`/`presentResult` 走**软验证**：旧日志参数不匹配时返回 `undefined` 降级通用卡片——展示永不 crash 重放。原始 JSON Schema 工具也可直接注册（自管校验）。

### 1.3 注册：ToolRuntime

`ToolRuntime`（`ctx.tools`）的 `register(definition)` 经 `ScopedLayers` 落层：**全局或 agent 作用域**（scoped 遮蔽 global）。注册即效应——`ctx.effect()`，fiber 卸载自动注销；`register()` 返回 disposer。伴生 API：`restrict({allow,deny})`（作用域工具过滤）、`guard(fn)`（pre-execute 后的单调否决守卫）、`presentAs(mode)`（作用域呈现声明）、`schemas(scope)`（模型面 schema 白名单投影）。`run_code` 名保留给 PTC transport。

## 2. 一次工具调用的完整执行管线

```
模型输出 ToolCallBlock {id, name, arguments(原始 JSON 字符串)}
  │
  ▼ 调度（agent-loop/tool-calls.ts）
session.append('tool/call')  ← 先落盘
executionMode 分类：isConcurrencySafe===true → 并行池(默认≤10) / 否则独占屏障
  │
  ▼ ToolRuntime.execute(exec) —— 五阶段（TOOL_RUNTIME_SCHEDULER 符号暴露给 loop）
① createExecution    参数一次递归物化 + deepFreeze；分配 opaque token；
                     PTC 折叠检查（mode:'ptc' 下模型直呼非 run_code → UNKNOWN_TOOL）
② tools/pre-execute  waterfall：PreToolDecision = allow | deny{reason} | cancel | ask
                     ask → ApprovalService.request()（无服务降级 deny）
                     此后 guardReason() 单调守卫：任何 guard 可否决，无 allow 翻案
③ tools/execute      waterfall（around-dispatch：超时/重试/指标包装器）
                     → dispatchToolBody() → tool.execute(args, exec)
④ 成功归一            返回值 validateJsonSchemaValue(output.schema)（违规 INVALID_TOOL_OUTPUT）
                     → deepFreeze → output.render() 生成模型面 content → presentationMeta
⑤ tools/post-execute waterfall：PostToolDecision = accept{content?|value?, additionalContexts?}
                                            | block{feedback, additionalContexts?}
                     → finalizeContent → materializeFinalResult → emit tools/result
  │
  ▼ 写回会话
session.append('tool/result', {message, error?, meta?, sourceEventSeqs:[callSeq]})
  │
  ▼ 附加效果
exec.deferContext(UserMessage) → 下一请求上下文
exec.concludeTurn()            → 标记回合终止
```

要点：

- **先落 `tool/call` 再执行**——即使进程崩溃，恢复器也能为未答复调用合成保守结果（见 [03 章 §6](03-Agent-Loop.md)）。
- **守卫是单调的**：guard 链没有 allow 结果，监听顺序无法翻案。
- **取消语义**：body 未启动 → `ABORTED_BEFORE_DISPATCH`；已启动 → `ABORTED`（promise 排干到静止）。
- **错误类型**：`ToolNotFoundError`（UNKNOWN_TOOL）、`ToolOutputError`（INVALID_TOOL_OUTPUT）、`ToolArgsError`（INVALID_ARGS）。

## 3. Capability Seam 模式

定义见 [../docs/glossary.md](../docs/glossary.md)：一个**能力接缝**完整包含三角色——**Service Definition**（声明接口）、**Service Provider**（实现）、**Consumer**（使用，通常是模型可见工具）。一个包可兼任多角色，但只有一个角色不算接缝；加能力意味着设计全部三个。

**样本一：dsh-shell（request/spec split 模板）**

- Service Definition：`ShellExecutor`（[shell/src/index.ts](../packages/shell/shell/src/index.ts)），`ctx.shell`——`abstract resolve(request): ShellExecSpec` + `abstract execute(spec): Promise<ShellExecution>`
- Provider：`bash-local` / `bash-sandbox` / `pwsh-local` / `pwsh-sandbox`（每组合恰好挂载一个，重复注册加载期报错）
- Consumer：[tool-bash](../packages/shell/tool-bash/src/index.ts)、tool-pwsh、persistent 变体

`resolve(request): Spec` 是显式的默认值填充步骤，绝不在 `run()` 里藏 `?? default`——这是根 AGENTS.md 点名的模板（"Explicit > implicit at package boundaries"）。

**样本二：dsh-llm 本身**——Definition 是 `LlmRuntime`，Provider 是各适配器，Consumer 是 agent-loop / compaction / session-title（见 [04 章](04-模型调用-dsh-llm.md)）。

同构家族：`ctx.fs`（fs / fs-local / fs-sandbox / tool-fs）、`ctx.web`、`ctx.lsp`（"Providers register capabilities, not tools"）、`ctx.computerUse`、`ctx.browserUse`、`ctx.subagents`。**接缝的威力**：fs 与 subprocess provider 共享一个执行世界，把它们指向远程沙箱，Bash、PTY、LSP 一起迁移，没有 provider 分叉。

## 5. 工具的 UI 呈现

设计约束（[adding-a-tool.md](../docs/cookbook/adding-a-tool.md)）：**Host presenters 是纯函数；Web cards 从原始事件派生**。

- 词汇表：[presentation.ts](../packages/core/tools/src/presentation.ts) 的 `ToolCallView`（Generic/Terminal/Diff 挂起态）与 `ToolResultView`（Generic/Terminal/Diff/Search/Read/Web 完成态），全部 `card` 判别联合。
- 工具用 `presentCall` / `presentResult` 声明渲染意图；纯函数（live 流式与日志重放**双跑**，禁 I/O/时钟/随机）；`presentationMeta` 产物持久化在 `tool/result` 事件的 `meta` 字段供重放复现卡片。
- 浏览器侧：[ui-tool](../packages/client/ui-tool/) **不消费** presenter 值——卡片由原始 `tool/call`/`tool/result` 事件 + 持久化 `result.meta` 派生，按 wire 工具名经 keyed slot `tool.call.toolview` 分发；未注册名走通用卡片 fallback。PTC 的 `subCalls` 渲染为递归子调用树。

## 6. PTC 模式（run_code transport）

[ptc.ts](../packages/core/tools/src/ptc.ts) 的 `createRunCodeTool`（config `mode: 'native' | 'ptc' | 'both'`）：PTC 模式下模型**只见 `run_code` 工具 + 生成的 SDK**（TypeScript/Python 类型由 `renderToolsSdk` / `renderToolsSdkPy` 渲染）；SDK 内的子分发携带 `parent` token 走同一管线；`tools/ptc-dispatch-log` waterfall 可改写持久日志副本（spill 策略挂接点）。preset `ptc` 即此形态的会话能力集。

## 7. deliverables：一个回合交付了什么

[deliverables](../packages/deliverables/) 组记录"回合交付物"：

- **tool-present**：`present` 工具——模型声明已交付的最终文件
- **workspace-changes**：每顶层 turn 的变更文件汇总（git 工作树快照），监听 `session/event` 追加 `workspace/changes` 事件

Web 端 `ui-deliverables` 在回合尾渲染两者。
