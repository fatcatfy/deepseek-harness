## 1. 命令体系

真源是 [package.json](../package.json) 的 scripts（Makefile 只是别名，可 `ARGS='--no-open'` 转发）：

| 命令 | 行为 |
|---|---|
| `pnpm dsh ...` | 源码启动 CLI（`node --import tsx/esm apps/cli/src/bin.ts`） |
| `pnpm run start:web` / `make web` | 源码启动 Web profile（默认 3080） |
| `pnpm run dev:web` | 完整 Web 开发循环：build → 三个 watcher（tsc client types / tsdown runtime / vite dist）→ serve |
| `pnpm run dev:desktop` / `start:desktop` | Electron 桌面应用（先准备打包运行时） |
| `pnpm dsh --profile headless "task"` | 一次性任务；`--json` 出 NDJSON 事件流；`--session-id` 续接；stdin 管道输入 |
| `pnpm run build` | 双编译面：Host（tsc host + tsdown）与 Client（tsc client + tsdown） |
| `pnpm run test*` / `doc-sync` / `website:build` | 见 [01 章 §6](01-架构总览.md) |
| `pnpm run demo:ptc -- "task"` | headless PTC 模式演示 |

**只有 `dsh` profile 是受支持的 Node 应用启动方式**（`verify-application-entrypoints` 门禁强制）；五种 shipped profile 见 [11 章 §2](11-扩展系统.md)。

## 2. CLI（apps/cli）

`dsh` npm 包本体。入口链：`bin.ts`(`runCli`) → `args.ts`(`parseDshArgs`——命令语法的唯一所有者) → `profile-boot.ts`(`runProfile`，也被 Desktop host 复用为 `@deepseek-ai/dsh/profile-boot`)。

- `dsh plugin --profile <name> ...`：插件/bundle 管理（profile 名与 `plugin` 命令重名时需显式 `--profile plugin`）。
- `dsh --profile web --dump-config` / `--dump-config-schema`：组合树审计（见 [11 章](11-扩展系统.md)）。
- headless 的行为契约：跑完单个持久化 session，stdout 打印最终答案，退出码 0/1。

## 3. Web

三段式架构：

```
浏览器                     Host 进程（dsh web）
┌──────────────┐   HTTP POST /api    ┌────────────────────┐
│ apps/web     │ ──────────────────▶ │ api/gateway        │
│ (Vite 壳)    │   WS /api/remote.mux│  (TypertGateway)   │
│  └ client/*  │ ◀────────────────── │ api/*-controller   │
│    60+ 包    │   (unary + 多路流)   │ host/webserver     │
└──────────────┘                     │ host/frontend-static│
                                     └────────────────────┘
```

### 3.1 Remote 层（packages/api）

- **编程模型**（[api-gateway.md](../docs/api-gateway.md)）：业务服务用 `@Remote` / `@RemoteScope` 标注方法，构建期生成 Host/Client 契约；`TypertLookupMap` 声明复杂对象的 wire 身份。
- **传输**：unary 走 HTTP POST 共享 `/api`；流走 Gateway 的 `/api/remote.mux` WebSocket（逻辑流多路复用，每条流可带 Client→Host 上行帧；2s 心跳）。
- **控制器包**：session-controller（命令/历史流/live 控制）、settings-controller、workspace-controller、terminal-controller、job-controller、workspace-files。
- **鉴权**：每次进程启动生成随机 launch token，`dsh web` 打印带 `?token=...` 的 URL，首次访问换取 authority 绑定的签名 cookie（HttpOnly、SameSite=Strict）；请求信任栏要求 Host loopback 或 trustedHosts、Origin 校验、拒绝 cross-site——`dsh web --host 0.0.0.0` 不支持。
- 断线重连：连接"代"机制 + 指数退避；`RemoteSnapshotStream` / `RemoteJournalStream` 提供快照+增量/分页+补洞语义；所有 unary 结果是 `RemoteResult<T>`。

### 3.2 浏览器半边（packages/client）

- 内核：`client/web`（`AppWebEntry` 两段式 boot）、`client/modules`（按 `dsh.client` manifest 声明加载浏览器模块）、`client/connection`（RPC/事件/重连）、`client/store`（React-free observable）。
- UI 家族 `ui-*`：conversation、chat、tool、approval、goal、settings、plugin-manager 等 40+ 特性包。
- **ConversationNodeDefinition**（[ui-conversation contract](../packages/client/ui-conversation/src/client/contract/conversation.ts)）：目标中立的会话节点模型——Session 事件经 Match/Location/Context 组装为 `ConversationSnapshot`；`ui-chat` 注册 inbox/message/assistant/turn-process/tool/command/compaction/retry/turn-error 等节点定义。加 Chat 节点 = 注册一个 Definition + keyed renderer（architecture.md "Where new behavior goes" 表的官方入口）。

### 3.3 Host 半边（packages/host）

`webserver`（命名路由/升级）、`frontend-static`（SPA dist 服务）、directory-picker 三后端、plugin-inventory 等。

### 3.4 apps/web

Vite 应用入口，`main.ts` 只运行 `new AppWebEntry(container).run()`；`tests/` 是浏览器快照 e2e（含 overlay 补丁如 pin-browse-picker）；dist 由 `dsh web` 服务。

## 4. Desktop（apps/desktop）

Electron 壳，包装**完整 dsh 生产运行时**：

- 技术决策：Electron 与 `@deepseek-ai/dsh` 永远同版本；`ELECTRON_RUN_AS_NODE=1` 跑共享 profile runner；捆绑 pnpm；独占 `$DSH_HOME/profiles/desktop`；默认 OS 分配端口；Windows EV 签名。
- 结构：`src/main.ts`（主进程）+ preload 系列 + `host-process.ts`（Electron Node 子进程启动 Host，加载 `dsh-app://app/` 打包 Web 入口）；Node IPC 承载 boot 注入/就绪/致命错误/关机。
- Web 拥有 RPC 与流；desktop carrier 只把本地页面接到已认证 Host。Shell-owned UI 经捆绑 pnpm 跑插件事务。
- 配套 `apps/desktop-host/`（私有 Desktop Host）与安装器/签名/公证脚本。

## 5. TypeScript SDK（packages/sdk）

| 包 | 职责 |
|---|---|
| protocol | wire 协议（NDJSON JSON-RPC + 命名 request/result/notification 类型） |
| client | `DeepSeekHarness` 高层 API + `HarnessClient` 低层 API |
| server | `jsonrpc` 插件：stdio 服务 SDK 客户端（`dsh --profile sdk`） |

高层 API 形态：

```ts
await using harness = new DeepSeekHarness({
  profile: 'sdk',            // 或 'sdk-minimal'
  patches, provider, model, reasoningEffort, maxTokens,
});
const result = await harness.run('say hi');
// RunResult { sessionId, finalResponse, events, notifications }
```

活动区间语义 = prompt 的 durable inbox receipt → 下一个整 agent idle。close 走 `shutdown` → stdin-EOF → SIGTERM → SIGKILL 梯子。server 侧 `initialize` 是就绪边界（等插件树 settle）；每 sessionId 一个 agent；stdout 只能有 JSON-RPC 帧。`subagent/subagent-dsh-sdk` 是 harness 内部消费者（用 SDK 把另一个 dsh 当子代理）。

## 6. Python SDK（python/）

两个包：

- `python/sdk`（`deepseek-harness-sdk`，模块 `deepseek_harness`）：高层 turns API + 低层 JSON-RPC client（`api.py` / `client.py` / `errors.py` / `models.py`）。
- `python/sdk-runtime`（`deepseek-harness-runtime-bin`）：捆绑的 dsh CLI 可执行 + native sidecars（五平台目标：linux-x64/arm64、macos-arm64/x64、win-x64）；运行时不需系统 Node.js。

```python
harness = DeepSeekHarness(
    dsh_home=...,            # 每次启动必须显式 Harness home（dsh_home 或 DSH_HOME），绝不静默用 ~/.dsh
    provider="deepseek-official", model=..., reasoning_effort=..., max_tokens=...,
)
result = harness.run("say hi")   # RunResult(session_id, final_response, finish_reason, events, notifications)
```

`finish_reason` = 最后一次根会话 `turn/end` 的 kind。持久定制：`--dump-default-config` 初始化后 `dsh plugin --profile sdk add file:...` 安装外部 bundle。贡献者工作流见 [python/development.md](../python/development.md)（`build-exe-for-python-sdk.ts` 构建 + pytest + smoke 场景）。

## 7. ACP（packages/acp）

标准 [Agent Client Protocol](https://agentclientprotocol.com) 的 **automation-only** 服务器：让程序与自动化通过 JSON-RPC stdio 驱动持久 DSH agent——创建/恢复会话、挂 MCP、选模型、发 prompt、收语义更新、答权限请求、取消工作，**全程无人类参与**。刻意只暴露标准 ACP v1 面（不含 DSH 展示卡/plan/todo/标题）。配套客户端 `subagent-acp`（out-of-process 子代理）。启动：`pnpm dsh --profile acp`。

## 8. 人机交互与反馈

- **interaction 组**：`commands`（slash 命令，免模型回合）、`user-approval`（一次性审批，无 answerer 时 fail-closed）、`permission-presets`（沙箱+审批捆绑成选择器）、`user-questions`（校验问答 schema + scoped answerer waterfall，agent 可暂停等人）、`tool-ask-user`（`ask_user_question` 模型工具）。
- **feedback 组**：`command-feedback`（会话级 `/feedback`）与 `message-feedback`（逐消息评分/备注；随会话存储、**永不进模型历史或遥测**）。
