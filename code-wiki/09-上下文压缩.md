# 09 上下文压缩 —— 当对话太长怎么办

> 官方参考：[../packages/compaction/](../packages/compaction/README.md)、[../packages/compaction/compaction-basic/README.md](../packages/compaction/compaction-basic/README.md)

## 1. 压缩工具箱总览

DSH 不只有"总结"一种手段，而是一套分层工具，从廉价到昂贵：

| 手段 | 成本 | 包 |
|---|---|---|
| 工具结果剪枝（确定性头/中/尾截断） | 零模型调用 | [compaction-tool-result-pruner](../packages/compaction/compaction-tool-result-pruner/) |
| 图片卸载（旧图换文本） | 零模型调用 | [compaction-image-offload](../packages/compaction/compaction-image-offload/) |
| 工具输出溢出 spill（见 [08 章 §7](08-上下文工程.md)） | 零模型调用 | spill-policy |
| 模型总结（checkpoint 化） | 一次模型调用 | [compaction-basic](../packages/compaction/compaction-basic/) |

## 2. 触发时机（compaction-basic）

`auto: true` 时注册三个触发器：

1. **步间压力**（`agent/pre-step`，trigger `'pressure'`）：`tokenMeter.measure(session).totalTokens` 超过阈值。阈值 = `thresholdRatio × contextWindow − headroomTokens − reservedCompletionTokens`（预留输出取请求头 maxTokens 或适配器默认）。先做一次可选的无模型 prune 再复测。
2. **上下文溢出恢复**（`agent/request-error` 且 code = `CONTEXT_WINDOW_EXCEEDED`，trigger `'context-overflow'`）：**绕过正常阈值与保留尾部策略**（`retainTokens=0`）强制缩减；成功则返回 `{kind:'retry'}` 重试请求；受 `maxOverflowRetries` 限制。
3. **手动**（`/compact` 命令 → `compactNow`）：低于阈值也可压缩有用历史；与 driver turn 经 `runMaintenance` 串行化。

## 3. 模型总结：summarizeWithLlm

[summarizer.ts](../packages/compaction/compaction-basic/src/summarizer.ts) 的设计非常讲究：

- **复用对话自己的前缀**：输入是"重放的对话前缀"——同一段 system prompt、tools、前导消息，再追加 `COMPACTION_INSTRUCTION` 作为最后一条 user 消息。这使辅助调用成为最后一次路由请求的**真前缀，复用 provider KV cache**（省钱且快）。
- **固定结构 checkpoint**：指令要求输出 Markdown（`## Primary Request and Intent / Key Technical Concepts / Files and Code / Errors and Fixes / Pending Jobs / Current Work / Next Step / Critical Context`）；已有 `<compacted-summary>` 块需合并不逐字拷贝。
- **落地定框**：`CHECKPOINT_PREAMBLE` 把总结节点框定为"既定背景"。
- `summarize()` 是子类唯一可覆写钩子（自定义模板/远端总结器的扩展点）。

## 4. 日志内事务：压缩协议

压缩是**日志内事务**（不是删除操作），事件序列（region.ts `compactSurfaceRegion`）：

```
compaction/start {compactionId, turn}          ← durable 锁
compaction/summary {summary, shadowedRange, shadowedSeqs, shadowedTokenCount,
                    provider, model, usage, rawOutput, llmStreamCall}   ← log-only
user/message（summary 内容, source: compact-checkpoint,
              surfaceOp: {op:'replace', startSeq, endSeq},
              sourceEventSeqs: 被遮蔽节点）      ← 紧随其后（"adjacency is contractual"）
compaction/end {compactionId, turn, error?}    ← 释放锁
```

关键语义：

- **旧消息不删除**：日志 append-only；`replace` 在 surface 上**遮蔽**（shadow）被替换节点——`deriveMessages()` 不再派生它们，但原始事件永远在。人类 transcript 用 `isAppendSurfaceEvent` 读追加起源事件，不受模型侧遮蔽影响。
- **shadow price 计量协议**：总结节点紧邻 summary 事件的排布是契约性的——token-meter 据此把总结的 token 记在被遮蔽历史的账上。
- **`compaction/summary` 记录哪个模型写了总结**（provider/model/usage/llmStreamCall）——总结调用本身也可从日志重建。
- 区间选择 `selectCompactableRange`：从第一个非 system 的 surface 节点开始（**surface 节点 0 的 system prompt 永不入选**），保留 `retainTokens` 预算的近期尾部，**绝不拆开 assistant 工具调用/结果对**（工具配对平衡断言）。

## 5. 无模型手段

### 5.1 tool-result-pruner

[ToolResultPruner](../packages/compaction/compaction-tool-result-pruner/src/index.ts)（`ctx.toolResultPruner`）：确定性按 Unicode 码点做头/中/尾剪枝，每节点替换用 `compaction/prune` 事件记录 shadow price。在压力触发时作为"先便宜后昂贵"的第一步先跑一遍再复测。

### 5.2 image-offload

[compaction-image-offload](../packages/compaction/compaction-image-offload/)：图片预算超限（`IMAGE_OFFLOAD_REQUIRED`）时把旧图片**永久**替换为"附件名 + 只读路径"文本并重试。经 `SessionMessageProjection` 实现为 logged selection（纯投影，见 [06 章 §3](06-消息系统.md)）。

## 6. 手动命令

`/compact`（[command-compact](../packages/compaction/command-compact/)）：idle 会话的手动压缩入口，经 `runMaintenance` 与 driver turn 串行化；先起 idle 任务、写 standalone `compaction/start`（`turn: null`）作为 durable 锁再总结——与自动压缩共享同一协议。

## 7. 与循环的关系

compaction-basic 是 `agent/pre-step` / `agent/request-error` 的纯消费者 + `runMaintenance` 的实现者——**不改循环一行代码**（"Plugins, not loop changes" 的样板，见 [03 章 §7](03-Agent-Loop.md)）。压缩后的 surface 让下一个 `deriveMessages()` 自然变短，循环无需感知压缩发生。
