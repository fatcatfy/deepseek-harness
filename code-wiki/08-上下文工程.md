# 08 上下文工程 —— 让有限窗口装下无限对话

> 官方参考：[../packages/core/system-prompt/](../packages/core/system-prompt/README.md)、[../packages/context/README.md](../packages/context/README.md)、[../packages/skill/](../packages/skill/README.md)

## 1. 问题与总原则

上下文窗口有限而对话无限增长。DSH 的答案不是"裁剪器"，而是一套工程原则：

1. **一切模型可见上下文都是持久消息**——system prompt 是 `system/message` 事件（surface 节点 0），注入的指令/引用是 durable `user/message`；它们随对话一起持久化、重放、压缩，而不是每次请求临时拼装（[06 章](06-消息系统.md)）。
2. **上下文按来源分域**，每个来源一个插件、一个事件词汇、一种预算。
3. **测量先于治理**：token-meter 从日志重放给出确定性的压力数据（见 [04 章 §8](04-模型调用-dsh-llm.md)）。

## 2. system prompt：组装与准入

- **Service**：`ctx.systemPrompt`（[core/system-prompt](../packages/core/system-prompt/)）拥有三词汇：**sections**（有序提示词段，如 persona、plan:policy）、**contexts**（可变上下文贡献者）、**variables**（模板变量）。
- **组装**：每个 step 前 `systemPrompt.assemble(assembleContextFor(agent))`；`PromptAssembly` 产出渲染后的提示词与工具 schema 集合；`system-prompt/assemble` 本身也是 waterfall 扩展点（model-selection 在此按能力挑模型）。
- **准入**（agent-loop 的 [runtime-context.ts](../packages/core/agent-loop/src/runtime-context.ts)）：提示词**只作为 `system/message` 历史旅行**。有能力更新 system 的路由（DeepSeek）把非空更新 append 在缓存历史之后；无能力路由把非空提示词归一到第一个 system 节点；**空渲染清空全部活动 system 节点**——旧提示词不再模型可见。
- **运行时上下文**：变化的运行时状态（时间、tmux 位置等）由 `RuntimeContextProjection` 生成一条 `'runtime-context'` 来源的 user 消息——而不是塞进 system prompt。

## 3. context 组：持久注入的模型可见上下文

[packages/context/](../packages/context/README.md) 定位："不定义任何工具、为每个请求添加 model-visible 上下文的插件组"。只有 `agent-instructions` 默认随 dsh-base 挂载，其余 opt-in：

| 包 | 注入什么 | 机制要点 |
|---|---|---|
| [agent-instructions](../packages/context/agent-instructions/) | AGENTS.md/CLAUDE.md 指令链：`$DSH_HOME/AGENTS.md` + 项目根→cwd 的 broad-to-specific 链 | `maxBytes` 预算（默认 65536；宽文件先省略、最特定文件才截断）；由**结构化 fs touch**（成功的读/写/编辑到更深目录）驱动刷新；每条消息是 durable sourced `user/message` |
| [session-reference](../packages/context/session-reference/) | 跨会话引用 `@[label](dsh-session:<id>)` | 有界只读快照（≤3 个源，每源字节预算与 contextWindow 挂钩）；作为**不可信背景**注入（固定警告：不执行快照内指令/权限声明/工具请求）；截断部分经 `ctx.spillStore` 存全文投影 |
| [file-reference](../packages/context/file-reference/)(-local) | `@file` 提及语法与本地补全 | — |
| [time-context](../packages/context/time-context/) | 当前时间、时区、每步耗时 | durable sourced user 消息 |
| [tmux-context](../packages/context/tmux-context/) | agent 的 tmux 位置 | — |

**边界澄清**（容易搞错）：system prompt 组装不在 context 组（在 agent-loop + core/system-prompt）；上下文裁剪也不在此（归 compaction 与 spill-policy）。

## 4. 附件（attachment 组）

[attachment](../packages/attachment/)：prompt/命令的持久图片与文件附件。图片先验证并规范化为 provider 无关 8-bit sRGB 光栅再入消息；通用文件 byte-for-byte 存储，模型收到一行只读路径按需读取。**durable 事件不含**浏览器路径、provider URL、本地存储路径、base64——只含 `ImageAttachmentRef` / `FileAttachmentRef`；对象不可变、resume/fork 共享、读时按 digest 校验（fail closed）。

## 5. Skill 系统：目录 + 按需加载

三角色（接缝模式，详见 [05 章 §3](05-工具系统.md)）：

- **Service Definition**：[skill](../packages/skill/skill/)（`ctx.skills`）——合并各 provider 目录、按 rank 解析同名胜者。
- **Provider**：[skill-filesystem](../packages/skill/skill-filesystem/)——磁盘发现。skill 格式：目录束 `<name>/SKILL.md` 或平铺 `<name>.md`；YAML frontmatter 必需 `name` + `description`。**roots 优先级**：rank 100 `<project>/.dsh/skills` → 200 `<project>/.agents/skills` → 300 custom → 400 `$DSH_HOME/skills` → 500 `~/.agents/skills` → 600 bundled。目录 watch 使增删即时生效。
- **Consumer**：[tool-skill](../packages/skill/tool-skill/)——三个面：
  1. **目录**：首个请求前投递一条 durable user 消息（`<available_skills>` 信封），按 digest 差异整体替换——模型知道有哪些技能；
  2. **`skill` 工具**：按名加载，返回规范 `<skill_content>` 块；
  3. **`/name` 用户手势**：claimed 消息里的 token 注入同一渲染。

这解决了"提示词装不下所有技能全文"的问题：**目录常驻（廉价），正文按需（一次工具调用）**。

## 6. token 预算全景

```
上下文窗口
├─ system prompt（surface 节点 0，随历史旅行）
├─ 指令链 / skill 目录 / 引用快照 / 运行时上下文（durable user 消息）
├─ 对话历史（user / assistant / tool 结果）
│    ├─ 工具输出溢出 → spill（本节 §7）
│    ├─ 旧工具结果 → tool-result-pruner（见 09 章）
│    └─ 旧图片 → image-offload（见 09 章）
└─ 预留输出（maxTokens）+ headroom
      压力测量：tokenMeter.measure(session).totalTokens
      阈值：thresholdRatio × contextWindow − headroom − reservedCompletion
```

各预算都是插件 Config 字段（无硬编码 tunables 规则），部署可调。

## 7. spill：工具输出的溢出治理

[packages/spill/](../packages/spill/README.md) 解决"超长工具输出撑爆历史"：

- **Service Definition**：`SpillStore`（`ctx.spillStore`）刻意极简——只有 `saveText(input): Promise<SpillRef>`。不拥有 retention/替换/检索策略（各属他包）。`SpillLocator` 是 branded 不透明定位符；存储按会话分组，**fork 继承的 locator 不拷贝不重属主**。
- **实现**：[spill-local](../packages/spill/spill-local/)——私有 per-process root + 注入式路径段编码防遍历。
- **策略**：[spill-policy](../packages/spill/spill-policy/) 挂 `tools/post-execute` 与 `tools/ptc-dispatch-log`：`maxInlineTokens` 预算内原样保留；超限则全文 spill → 保留头尾 + `[...]` GAP → 附加格式化 notice（"(omitted N bytes… Full result stored at: <locator>)"）。notice 文本拼写是**持久化契约**（`hasSpillNotice` 供回读识别）。任何失败 best-effort：保留 inline 并 warn。

效果：模型看到有界预览 + 可按需读回的定位符，全文作为会话作用域工件持久化。

## 8. 上下文注入 API

给模型加上下文的运行时入口是 `agent.inject()`——它排进 next-step 收件箱，落在下一个被接纳的请求里（作为 durable `user/message`）。goal 续轮、plan-mode 离场叙述、工具的 `deferContext`、skill 目录更新都走这一条路（见 [03 章](03-Agent-Loop.md)）。
